## 内存优化

主进程原先加载了第三方输入法组件。用量条没有可编辑输入框，因此在创建窗口前，通过 `ImmDisableIME` 关闭本工具 UI 线程的输入法支持。范围仅限本工具的线程，中文绘制、菜单和其他应用的输入法保持可用。未增加框架或后台服务。

依据：[微软 ImmDisableIME 文档](https://learn.microsoft.com/en-us/windows/win32/api/imm/nf-imm-immdisableime)。

## CLI 缓存与磁盘占用

原作者在 v0.1.4 的 [fa64ce1 修复](https://github.com/configcrate/codex-titlebar-meter/commit/fa64ce117a02540eb636fd7d7c0099f99a913526) 中，清理了 Codex 更新留下的旧版 CLI 副本；此 Fork 已包含该提交。参见[原仓库说明](https://github.com/configcrate/codex-titlebar-meter#数据与隐私)。

本机目前只有一份当前 CLI 缓存，约 325.5 MiB；这是磁盘文件大小，不是内存占用。缓存路径为 `%LOCALAPPDATA%\ConfigCrate\CodexTitlebarMeter\desktop-cli`。清理代码只处理本工具生成的包命名目录与可识别文件，保留当前版本和其他内容，遇到 Windows 锁定文件时留待以后处理。

本次已验证安装目录原始 CLI 的 `--version` 可以直接运行，但尚未验证直接运行时的完整额度会话、普通用户权限和 Codex 更新行为。因此本次没有改变复制缓存策略，也没有声称实现了零缓存。

## 保持轻量的边界

- 沿用原生 Rust + Win32/GDI，不引入 WebView、Electron 或额外 Windows 服务。
- 没有 Codex 窗口时，额度工作线程等待；现有会话结束后清理额度读取子进程。
- 额度默认每分钟刷新，并响应服务端更新通知；窗口位置检查与额度请求分开。
- 后续资源检查同时统计主程序、子进程与磁盘缓存，不只报告 exe 体积。
